# اقتصاد واقعی ×۱۰۰۰ — راهنمای مهاجرت

این تغییر مقدار واقعی پول را در دیتابیس ۱۰۰۰ برابر می‌کند؛ دیگر فقط نمایش پول در رابط کاربری بزرگ نمی‌شود.

## چه چیزهایی مقیاس می‌شوند؟

- خزانه، دستمزد، بودجه خدمات و دفتر حساب
- قیمت سهام، کالاها، سفارش‌های بورس و بازار تسلیحات
- قیمت واحد معاملات و هزینه ترانزیت قراردادها
- مبالغ نقدی قراردادهای تجاری و وام‌های سازمان بین‌الملل
- درآمد مالیات، تولید، تعرفه و درآمد روزانه ساختمان‌ها
- خزانه اولیه کشورها و قیمت‌های مرجع ساختمان/تسلیحات

مقادیر فیزیکی منابع (غله، آهن، زغال، پارچه، سوخت و برق) در این مهاجرت ضربدر ۱۰۰۰ نمی‌شوند.

## رفتار هنگام استقرار

Migration شماره‌ی `002_economy_scale_1000.sql` به‌صورت تراکنشی و فقط یک بار اجرا می‌شود؛ نسخه‌ی آن در `schema_migrations` ثبت می‌شود. در صورت عبور مقدار از محدوده‌ی `BIGINT`، مهاجرت با خطا متوقف می‌شود و تراکنش rollback می‌شود.

**مهم:** پس از ادغام این PR و استقرار روی Railway، برنامه در startup مهاجرت ۰۰۲ را روی دیتابیس متصل اجرا می‌کند. این PR هنوز روی دیتابیس Railway اجرا نشده است.

## قبل از استقرار روی دیتابیس اصلی

1. از Railway PostgreSQL یک backup/snapshot قابل بازیابی بگیر.
2. ابتدا برنامه را با `APP_ENV=test`، توکن ربات آزمایشی و `TEST_DATABASE_URL` روی دیتابیس جداگانه اجرا کن.
3. روی دیتابیس هدف، دستور زیر فقط خواندنی است و مقادیر فعلی/پیش‌بینی‌شده را گزارش می‌کند:

   ```bash
   npm run migration:preflight
   ```

4. اگر preflight موفق بود، backup را بررسی کن و سپس استقرار نسخه‌ی جدید را انجام بده.

## بازگشت

فایل `migrations/down/002_economy_scale_1000.sql` برای بازگشت دقیق تهیه شده است. ابتدا بررسی می‌کند همه‌ی مقادیر پولی بر ۱۰۰۰ بخش‌پذیر باشند؛ اگر نباشند، اجرا را متوقف می‌کند و توصیه می‌کند backup قبل از مهاجرت restore شود. این فایل در startup خودکار اجرا نمی‌شود.

به‌دلیل این‌که مهاجرت داده‌های موجود را تغییر می‌دهد، PR را تا زمان تأیید صریح اجرای migration روی دیتابیس اصلی باز نگه می‌دارم.
